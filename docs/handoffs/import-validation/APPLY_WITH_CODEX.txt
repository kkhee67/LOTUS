이번은 미커밋 소스 diff 전달이다. importer 전용 커밋·PR은 아직 없다.

패키지에는 importer.patch, 실제 source/ 파일, delivery.json, verify_delivery.py가 있다.
source/는 내용 검토용이며 통째 덮어쓰지 마라. patch 방식으로만 안전하게 적용해라.
공통 문서 패키지 B는 별도 검토용이며 importer 실행에 필요하지 않다.

1. 현재 루트·remote·HEAD·브랜치·stage·미커밋·미푸시 변경을 확인하고 보존해라.
2. 기존 사용자 작업이 있으면 별도 안전한 작업 공간을 사용해라. 임의 reset/stash/삭제 금지.
3. 공통 기반 커밋과 AGENTS.md, 계약 문서를 읽고 이 폴더의 HANDOFF.md/VERIFY.md/manifest.json을 읽어라.
   docs/PROGRESS.md 같은 별도 공통 문서는 A 패키지에 없어도 정상이다.
4. 패키지를 저장소 밖에 풀고 다음을 실행해라. <package>는 압축 해제한 패키지 절대 경로다.
   python <package>/verify_delivery.py
   python <package>/verify_delivery.py --target <검토 저장소 절대경로> --phase before
   검토 저장소 루트에서: git apply --check --whitespace=error-all <package>/importer.patch
   확인 후: git apply --whitespace=error-all <package>/importer.patch
   python <package>/verify_delivery.py --target <검토 저장소 절대경로> --phase after
5. 새로 만든 파일까지 포함되는지 manifest와 비교하고 VERIFY 명령을 실제 실행해라.
   이미 파일이 존재하거나 내용/기준이 다르면 적용을 멈추고 차이를 보고해라.
   원격 main 또는 PR 기준이 바뀌었다면 기존 패키지를 강제 적용하지 말고 새 기준 검사를 요청해라.
6. 실제 검토·개선 결과와 기존 인계 구현을 구분한다. 원래 커밋 작성 정보는 바꾸지 않는다.
   이번 diff에는 새 커밋 작성 정보가 없으며, 단순 적용을 독립 설계·구현으로 기록하지 않는다.
7. 사용자에게 승인받은 범위에서만 commit/push/PR을 수행한다. main 직접 push/자동 병합/force push 금지.
8. 실제 main 병합은 다른 팀원의 검토 후 사람이 진행한다. 확인하지 않은 검토·피드백을 기록하지 마라.

패키지의 기준 적용 검사는 검토용 초안에서 수행한 것이며 승인된 main에서의 성공이 아니다.
건희: 반복 입력·오류 롤백·스키마/복구 정책 확인. 시영: 네 배열·같은 배치 출처·모드·ID 조건 확인.
