# Git 작업 절차
1. 상태·remote·HEAD·미커밋 변경·원격 브랜치·PR과 적용 지침을 확인한다.
2. 승인된 main을 fetch하고 작은 작업용 codex/<role>/<task> 브랜치를 만든다.
3. 기존 변경은 삭제/reset/임의 stash하지 않는다. 타 담당 브랜치·코드를 무단 수정하지 않는다.
4. 담당 범위 구현과 검사를 마치고 변경·결과·미실행을 기록한다.
5. 사용자 승인 범위에서만 commit/push/PR 생성한다. 다른 팀원이 검토하고 사람이 병합한다.
main 직접 push, 강제 push, 보호 약화, 검토 우회, auto-merge는 금지한다.

## 현재 초기화 인계
사용자가 기존 codex/bootstrap 브랜치를 이어 수정하도록 명시적으로 승인했다.
기준 f1997c3c45d4259c2d09d30d5e052df0b069f984, 기존 PR #1.
최초에는 로컬 수정·검사만 승인되었고, 이후 사용자가 GitHub 업로드와 팀 인계를 승인했다. 기존 작업 브랜치 커밋·push와 PR #1 설명 갱신을 진행하며 main 병합은 포함하지 않는다.
다음 업로드 시 원격 HEAD를 다시 확인하고 원격이 변경됐다면 충돌을 조율한다.
과거 AI 준비 문서는 codex/ai/basic-recommendations의 aaf6fc7에 보존되어 있다.

공통 변경은 요청 이유·필드·영향 담당·호환성·검사 계획을 정리하고 별도로 검토한다.
PR에는 기준 SHA, 계약 버전, 범위, 검사 명령·결과, 미구현·미실행을 적는다.
main에 반영된 SHA를 확인한 뒤 팀원이 해당 기준에서 작업한다.
