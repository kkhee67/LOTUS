# 서비스 기획
경험이 부족한 청년의 질문 “지금 내 상황과 관심으로 어떤 기회에 참여하고 무엇을 준비할까?”에 답한다.

## 입력
나이, 학교, 학적·학년, 전공, 관심 분야, 거주지역, 활동·경험, 희망 직무와 근무지역, 자유 목표.
전공·관심·희망 직무·목표 중 유효한 하나만 있으면 시작한다. 나머지는 선택이다.
빈 문자열은 유효하지 않으며 입력하지 않은 선택 문자열은 null/생략을 사용한다.
활동 none과 unknown, 거주지와 희망 근무지, 관련 전공과 지원 자격 전공을 구분한다.
학교와 나이로 능력·취업 가능성을 점수화하지 않는다.

## 출력과 우선순위
1. 사용자 입력 → 실제 공고 추천 → 근거·지원 전 확인 사항 → 상세 → 원문 이동.
2. 근거 있는 직무 설명 → 선택 가능한 다음 활동 → 실제 경험에 바탕한 면접 연습.
3. 동의 기반 외부 AI 설명 보조와 기능별 실패 처리 검증.
공모전, 경진대회·해커톤, 취업·신입·인턴, 자격증, 설명회·박람회, 학교 공지 등을 다룬다.
인턴은 job subtype, 설명회·박람회는 event subtype이다. 학교는 출처이며 학교 게시 채용도 job이다.
추천 관련성은 합격 확률이 아니다. 일반 준비 행동과 실제 모집 공고를 구분한다.
공식 멘토링 링크만으로 실제 매칭 완료를 주장하지 않는다.

## 이번 범위
공통 모델·API·실행 골격·예시·검사·인계. 추천 계산은 구현하지 않는다.
공통 기반이 검토되어 main에 반영되고 사용자가 다음 작업을 요청한 뒤 기본 추천을 구현한다.
그 뒤 기본 추천 연결, 직무, 활동 계획, 면접, 외부 AI, 통합 검증을 별도 작업으로 진행한다.

## 제외·개인정보
이번에 DB 본개발, 완성 UI, 실제 수집기, 외부 AI, 실제 멘토 매칭·채팅·예약·결제를 구현하지 않는다.
학교 공지는 후속 작업에서 공개 출처 한 곳부터 시작한다. 모든 학교를 지원한다고 주장하지 않는다.
프로필은 요청·화면 메모리에서만 사용하고 URL·DB·로그·분석 도구에 남기지 않는다.
localStorage를 도입하더라도 관심 공고 ID만 저장한다. 현재 localStorage는 사용하지 않는다.
생년월일·상세 주소·학교 로그인·주민번호·연락처를 요구하지 않는다.
